# Audit, November 2026

Done by reading the code and driving the production build in Chromium at 1440, 834 and iPhone 13 widths, in light and dark mode, from the point of view of a first-time visitor with a workflow to fix.

## First-visit read

The promise is clear in one line ("Turn your workflow into a plan you can build") and the samples give a result in under a second. Where it lost me was after the brief opened: the first thing I saw was a six-row form full of "Needs confirmation", not the answer. The tool's best output, the recommended move, was below the fold.

## Output reliability

What already works well, and should be kept: facts must quote the user's own words (`groundReport` downgrades anything unquoted), hours come from code not the model, and every failure path falls back to the deterministic brief.

What to add, in order:

1. **Schema-constrained output.** Replace the fenced-JSON-in-prose contract with `streamText({ output: Output.object({ schema }) })` (or a second `generateObject` call after the spoken reply). The parser currently drops malformed JSON silently; a schema turns that into a retry.
2. **A golden set.** 20 to 30 real workflows (the four starters plus anonymised SOPs) with expected steps and "must not claim" lists. Score: step recall, fact-quote validity (already computable with `quoteAppearsIn`), invented-number rate, and plan completeness (no empty Trigger / Failure). Run it in CI against the demo agent on every PR and against the live model nightly with a capped key.
3. **Output guards in code.** Reject or downgrade any hour, dollar or headcount figure in model output that is not in the source, the same way facts are grounded today.
4. **Deterministic first, model second.** The rule-based brief is already good for well-structured input. Route short, list-shaped input to rules and only send messy SOPs, PDFs and images to the model. That cuts both cost and variance.

## Objective output: the n8n scaffold

The brief now exports an **importable n8n workflow** (`workflow-scaffold.n8n.json`). It is a Manual Trigger, one No Operation node per plan step named by its kind ("2. Validate · Check required fields…"), each with a note saying what to replace it with, plus sticky notes for inputs, human review, failure handling and launch tests.

It is inert on purpose: nothing can send, write or spend on import. That makes it safe to hand to anyone, and it turns "here is advice" into "here is the skeleton, swap five nodes". Example: [`docs/n8n/example-data-review.n8n.json`](n8n/example-data-review.n8n.json). It follows the n8n export format but has not yet been imported into a live n8n instance in CI; do that once by hand before promoting the feature.

Next step if it earns usage: map kinds to real nodes when the user named the tool (Google Sheets, Outlook, Slack) and leave No Operation otherwise.

## Cost

| Option | Cost | Trade-off |
| --- | --- | --- |
| Rule-based only (today's production) | $0 | Good on list-like input, weak on messy prose, cannot read images |
| OpenAI `gpt-5-mini` (default live path) | Low, per token | Best tested path in this repo |
| Any OpenAI-compatible endpoint: OpenRouter, Groq, Google's Gemini OpenAI endpoint, self-hosted vLLM or Ollama | Free tiers to very low | Set `LLM_BASE_URL`, `LLM_API_KEY`, `MODEL`. Free tiers are rate-limited and some providers may use free-tier inputs for training: read the terms before sending customer workflows |
| Hybrid (recommended) | Lowest per useful brief | Rules for structured input, model only when rules extract fewer than three steps or files are attached |

The provider switch is in `lib/model-provider.ts`. OpenAI-only options (reasoning effort) are no longer sent to other providers.

Other savings: prompt caching works automatically on OpenAI for the long, static system prompt, so keep it first and unchanged. Cap PDF text (already 12k chars). Keep `LIVE_DAILY_REQUEST_LIMIT` set in production.

## Security and guardrails

Already in place: a strict request allowlist (roles, part types, inline-only attachments, size caps), server-side rebuild of history, prompt-injection instruction in the system prompt, attachment text kept as user data never system text, per-IP and daily limits, a 45s timeout.

Added in this pass:

- Security headers on every route: `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, strict referrer, a locked `Permissions-Policy`, HSTS, and no `X-Powered-By`.
- `GET /api/optimize` no longer discloses the model name.

Still needed before a public paid model:

1. **Durable rate limits.** The current limiter is per function instance. Use Vercel Firewall rate-limit rules or an Upstash Redis sliding window keyed on IP.
2. **Bot protection** on `POST /api/optimize` (Vercel BotID or Turnstile) so the free endpoint cannot be scripted.
3. **A provider-side spend cap** on the API key itself, not just the in-app daily counter.
4. **A full CSP** with nonces once the page can be dynamic.
5. **PII warning that acts.** A cheap regex pass for emails, phone numbers and card-like numbers that asks before sending to a model.
